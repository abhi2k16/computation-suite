# Consolidated Future Roadmap: Deployment Sequence

**Compiled from:** every `.md` document in `fea_engine/docs/` — `general_purpose_extensions_roadmap.md`, `generalized_mesh_grading_roadmap.md`, `geometric_nonlinear_shell_roadmap.md`, `geometry_meshing_alternatives_research.md`, `nonlinear_transient_dynamics_roadmap.md`, `fem_implementation_lessons.md`, `nonlinear_fem_lessons.md`, `tensormesh_comparative_analysis.md`, and (as of the 2026-09-13 reconsolidation, Wave 11 below) `tensormesh_analysis_report.md`.

**What this is:** almost everything originally planned in the five roadmap/research documents has already been implemented and validated (visible in each document's own "implemented"/"validated" status lines). This document collects only what is left — every item explicitly flagged across all eight documents as not-yet-done, deferred, a documented dead end still worth revisiting, or a gap surfaced by the two textbook-lesson audits and the TensorMesh comparison — and orders it into one build sequence.

**Ordering logic:** items are sequenced by (1) stated dependencies (a document sometimes says outright "X depends on Y" or "X was deferred until Y matures" — those constraints are followed exactly), (2) effort/risk, cheapest and most self-contained first, and (3) how many separate documents independently flag the same gap (items named more than once across documents are treated as higher-confidence priorities and pulled earlier). Waves are meant to be read in order; items inside the same wave have no ordering constraint against each other and can be done in any sequence or in parallel.

## Wave 10 — Differentiable correction / ROM-training infrastructure (Saverio et al. 2026)

Sourced from a single external paper, not the eight original roadmap documents: Saverio, Bucci, Farro, Content and Sipp, "An end-to-end PyTorch interface for differentiable PDE solvers: A RANS model-correction study" (*Data-Centric Engineering* 7:e37, 2026, doi:10.1017/dce.2026.10066), reviewed with the user (2026-09-12) and scoped into this wave immediately after. The paper couples an existing Fortran RANS solver (BROADCAST, differentiated with Tapenade) to PyTorch so that a trainable additive correction $f_\vartheta(w)$ can be optimized end-to-end against reference data, via either an explicit residual-minimization layer or an implicit Newton layer whose backward pass solves an adjoint system instead of unrolling the Newton iteration. **The mathematical framing ($R(w)+f_\vartheta(w)=0$, explicit-vs-implicit differentiable layers, adjoint-based training) is domain-agnostic** — the paper itself names solid-mechanics constitutive modeling as a direct analogue (§2.3) — and maps closely onto where this package is already headed: `fea_engine`'s own Wave 9 established the `backend=`/`method="autograd"` opt-in pattern for individual linear solves and element tangents, but stopped short of anything resembling the paper's actual point, training a correction term against data. This wave is that next step, plus the specific pieces of the paper judged directly reusable for the sibling `NonLin-HyROM`/`Multi_Fidelity_NL_Structural_ROM` projects (surrogate/ROM correction is structurally the same problem as RANS closure correction — a cheap baseline model plus a trainable, data-calibrated additive term).

**Ordering logic**: item 98 (the implicit differentiable-solve layer) is the one genuine prerequisite — items 99-100 are far more useful once it exists, though 100 (explicit calibration) can be built and validated independently and first, as a lower-risk warm-up exactly the way the paper itself validates its explicit strategy before its implicit one (§4.1.2 before §4.1.1 conceptually, though the paper presents them in the opposite order). Items 101-102 are cross-cutting correctness/performance concerns that apply to whichever of 98-100 lands first. Item 103 is the actual payoff for the sibling ROM projects and depends on 98-100 existing in some form. Items 104-105 are small, low-risk, standalone utilities lifted from the paper's appendices, useful the moment ANY trainable component exists in this package but not blocking anything.

Sourced from three external documents reviewed with the user (2026-09-15): Yang, Luo, Yang, Nan, Chen & Sun (2025), "FE reduced-order model-informed neural operator for structural dynamic response prediction" (FRINO), *Neural Networks* 188:107437; Dummer, Ye & Brune, "RONOM: Reduced-Order Neural Operator Modeling" (arXiv:2507.12814); and the sibling `generative-prediction-of-laser-induced-dynamic-latent-space-representations/L-NeuralODE` repository the user pointed at directly — reviewed for its parameterized-latent-ODE-plus-curriculum-learning ARCHITECTURE only, since its own application (a CNN-autoencoder-compressed laser-induced field on a regular 592×240 pixel grid) has nothing to do with this project's FE meshes. ## Wave 17 — Geometrically exact rod + intrusive POD-ROM track (Georgiou 2005)

Sourced from a gap analysis done with the user (2026-09-28) against Georgiou, I. T. (2005), "Advanced Proper Orthogonal Decomposition Tools: Using Reduced Order Models to Identify Normal Modes of Vibration and Slow Invariant Manifolds in the Dynamics of Planar Nonlinear Rods," *Nonlinear Dynamics* 41:69-110 (PDF in the sibling project `ROM_formulations/POD_ROM_Nonlinear_Rods/`). The paper projects the exact planar Cosserat-rod equations (its Eqs. 1-3) onto 3 POD modes taken from FE dynamics. It then uses the linearized 3-DOF reduced system (its M, D, K and eigenvectors, the "POD-RM" method) to decide when a dominant POD mode is a nonlinear normal mode, and shows a master-slave slow invariant manifold.

**Why the current packages are not sufficient (checked directly, not assumed).** Built on `Beam2DCorotational` (the only planar large-rotation element), the paper's pinned-pinned rod (Table 1: L=10, A=1, 1x1 section so I=1/12, E=12000, G=5000, rho=1e-6) gives 3121.0 / 28089.4 / 78026.1 rad/s for bending modes 1/3/5. The paper's reduced-model frequencies (Eq. 50) are 3078.55 / 25214.6 / 60986.5. A closed-form pinned-pinned Timoshenko beam with shear factor kappa=1 and rotary inertia gives 3078.5 / 25214.0 / 60981.7, matching the paper to <0.01%. So the paper's model is a shear-deformable rod with kappa=1, and `Beam2DCorotational` (Euler-Bernoulli, no rotary inertia, rotation tied to the slope) is off by 1.4% / 11% / 28%. It also cannot produce an independent rotation field, which the paper's rotation-component norms depend on (C_3k = 0.29 / 0.59 / 0.73 for its 1st/3rd/7th modes, Table 17). The paper's "3rd" and "7th" normal modes (numbered from its Table 2) are bending modes 3 and 5. The paper's Table 2 axial frequencies (1r = pi*c/L = 34414) and the 2r = 68829 frequency that appears in its Eq. 53 imply axially immovable pins (u1 = u2 = 0 at both ends), which fixes the boundary conditions below.
